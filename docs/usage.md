# Використання команд Copilot Chat

Команди проєкту — це prompt-файли у `.github/prompts/`. У VS Code відкрийте
Copilot Chat, введіть `/` і виберіть потрібну команду зі списку. Також можна
відкрити потрібний `.prompt.md` і натиснути кнопку запуску або скористатися
**Chat: Run Prompt...**.

Команди змінюють лише файли, потрібні для своєї задачі, зберігають сумісні
наявні налаштування та мають повідомляти про помилки, а не вигадувати
успішний результат.

## Доступні команди

| Команда | Призначення |
| --- | --- |
| `/git-init` | Перевірити Git-репозиторій, додати до `.gitignore` відсутні шаблони `node_modules/`, `dist/`, `*.log`, `.DS_Store` і показати статус Git. |
| `/create-project` | Використати skill `project-scaffold` для створення мінімального TypeScript scaffold: `package.json`, `tsconfig.json`, `src/index.ts` і `.gitignore`. |
| `/create-build` | Використати skill `build-and-test`, налаштувати залежності TypeScript/Vitest, npm scripts і тести `add` та `hello`. |
| `/create-actions` | Використати skill `github-actions`, створити скрипти CI для Bash і Windows та GitHub Actions workflow з матрицею трьох ОС. |
| `/check` | Перевірити файли, конфігурації, збірку, тести й workflow без редагування файлів. |
| `/init` | Послідовно виконати повний цикл: `git-init` → `create-project` → `create-build` → `create-actions` → `check`. |

`/create-project`, `/create-build` і `/create-actions` посилаються на відповідні
описи в `.github/skills/`. Команда `/init` оркеструє їх у вказаному порядку та
зупиняється при першій помилці.

## Повний цикл ініціалізації

1. Відкрийте Copilot Chat у корені workspace `404CSAD18`.
2. Введіть `/init` і виберіть prompt **init**.
3. Перевірте запропоновані зміни, особливо якщо репозиторій уже містить
   користувацькі файли або налаштування.
4. Оркестратор виконує етапи послідовно та зупиняється, якщо етап завершується
   помилкою або виявляє блокувальний конфлікт. Звіт має вказати останній
   завершений етап, помилку та кроки, які не запускалися.
5. У разі зупинки усуньте повідомлену причину та повторно запустіть `/init`.
   Команди розраховані на ідемпотентне повторне виконання: вони повинні
   зберігати сумісні налаштування та не дублювати записи.

Для виконання окремого кроку запустіть відповідну команду `/git-init`,
`/create-project`, `/create-build` або `/create-actions`.

> npm вимагає, щоб назви пакетів були в нижньому регістрі. Тому маніфест
> використовує `"name": "404csad18"`; ідентифікатор репозиторію в документації
> лишається `404CSAD18`.

## Перевірка проєкту

Запустіть `/check` у Copilot Chat, щоб перевірити обов'язкові файли, JSON
маніфесту, TypeScript-конфігурацію, скрипт збірки, тести Vitest і структуру
`ci.yml`.
Перевірка не повинна редагувати файли або запускати CI wrapper scripts.
TypeScript збірка виконується без генерації `dist` за допомогою
`npm run build -- --noEmit`. Тести запускаються через `npm test`. Якщо
залежності, інструменти синтаксичного аналізу або обов'язкові файли відсутні,
звіт має позначити перевірку як невиконану та пояснити причину; `/check` не
встановлює залежності й не виправляє файли.

## Ручний запуск збірки й тестів

У терміналі з кореня проєкту виконайте:

```sh
npm run build
npm test
```

`npm run build` запускає TypeScript compiler через npm script `build`, а
`npm test` запускає Vitest у режимі одноразового виконання. Для першого
встановлення залежностей використовуйте `npm ci`, якщо в репозиторії є
`package-lock.json`.

Для CI-перевірки вручну можна запустити відповідний wrapper:

- Linux/macOS: `bash scripts/ci.sh`
- Windows: `scripts\ci.bat`

Ці скрипти виконують `npm ci`, збірку та тести. Для перевірки всіх трьох
операційних систем потрібен запуск workflow на GitHub Actions; локальний запуск
одного скрипту не підтверджує результати інших runners.
